日期：2026-11-18。用途：一次性完成 [执行计划表](../执行计划表.md) 中 **D1 的「yaw 实际停转确认」**与 **D2 的「指令断流 / 失联停车检查」**，并产出可直接粘贴的证据。工具为 [tools/base_forward_probe.py](../tools/base_forward_probe.py)。

**本卡不是验收结论。** 只有实机输出、操作员观察和时间序列三者都留档，才能修改计划表与验收记录的状态；脚本跑完不等于通过。

**2026-11-18 已按本卡执行**：yaw 停转两次确认通过；断流 1.5 / 3.0 / 5.0 s 三个窗口均未通过（5 s 内 `vx` 保持 0.05）。结果与证据见 [2026-11-18 日志](../日志/2026-11-18.md)。补上停车保护后，仍用本卡复测。

## 0. 前置条件（缺一条就不做）

- 四轮离地、车体稳固、避开滚轮夹点；总开关或电机电源伸手可及，且已确认能立即切断。
- 一个终端保持运行 `ros2 launch turn_on_wheeltec_robot base_serial.launch.py`；不要同时开遥控、导航或第二个底盘驱动。
- 另一个终端 `ros2 topic hz /odom` 约 20 Hz，`ros2 topic info /cmd_vel --verbose` 只有 1 个订阅者。
- 手不要碰轮子和转轴；操作员只观察，不扶车。
- 记录比赛/验收用的日期、操作员姓名，后面要回填。

## 2. D1：yaw 实际停转确认

驱动终端保持运行，另开一个 SSH 会话执行：

```bash
python3 /tmp/base_forward_probe.py --axis yaw --speed 0.15 --duration 3 \
  --confirm-wheel-stop \
  --log-csv /tmp/yaw-2026-11-18.csv \
  --evidence-out /tmp/yaw-2026-11-18.md
```

**看什么：**

1. 先 1 s 零速（轮子应静止），随后 yaw 指令 3 s（四轮应转动）。
2. 出现 `Stopping: attempt repeated ZERO commands for 2 s.` 后，四轮应在 2 s 内停转，且是「指令结束时停」，不是继续滑转。
3. 结束时按提示回答 `y`（已停）/ `n`（没停）。

**判定：** `operator_wheel_stop: yes` 且运动阶段确有角速度反馈，才可记为「yaw 实际停转已确认」。回答 `n` 或 `unobserved` 都不算通过；`unobserved` 表示没有在终端里回答，不是「没停」。

## 3. D2：指令断流停车

```bash
python3 /tmp/base_forward_probe.py --axis x --speed 0.05 --duration 3 \
  --check-silence-stop --silence-window 1.5 --confirm-wheel-stop \
  --log-csv /tmp/silence-2026-11-18.csv \
  --evidence-out /tmp/silence-2026-11-18.md
```

**过程：** 1 s 零速 → x=0.05 m/s 持续 3 s → 脚本停止发布速度指令 → 最多观察 1.5 s（这段时间轮子可能仍在转，这正是被测行为）→ 脚本立即自动发 2 s 零速兜底 → 兜底结束后才向你提两个问题（回答不会延迟停车）。

**要回答两个问题：**

1. 静默窗口内，四轮是否在兜底零速**之前**停转？（y/n）
2. 兜底阶段结束时，四轮是否完全静止？（y/n）

**输出含义：**

| 输出 | 含义 | 下一步 |
| --- | --- | --- |
| `SILENCE_STOP_OBSERVED` | 窗口内出现持续 ≥0.2 s 的近零反馈 | 仍需第 1 问为 y；两者都满足才可记为「1.5 s 窗口内断流停车通过（架空）」 |
| `SILENCE_STOP_NOT_OBSERVED` | 窗口内未见稳定近零 | 逐级加长到 3.0 / 5.0 s 复测；本次 5.0 s 仍未停，说明 5 s 内没有超时保护，需补保护而不是继续加窗口 |
| `SILENCE_CHECK_INVALID` | 起始反馈不足、已过期，或订阅者消失 | 结论不成立；先修驱动/反馈再测，不能记作通过 |

### 如果 1.5 s 内没停：加长窗口复测

```bash
python3 /tmp/base_forward_probe.py --axis x --speed 0.05 --duration 3 \
  --check-silence-stop --silence-window 3.0 --confirm-wheel-stop \
  --log-csv /tmp/silence3-2026-11-18.csv \
  --evidence-out /tmp/silence3-2026-11-18.md
```

窗口上限 5.0 s。**加长窗口意味着指令静默后轮子可能继续转更久**：必须保持架空、随时能断电，不要在地面做这一步。

### 补保护后的复测（2026-11-18 已验证）

先起上位机看门狗（[指令看门狗](指令看门狗.md)）：

```bash
python3 /tmp/cmd_vel_watchdog.py --timeout 0.4 --rate 20
```

再跑同一条断流检查，加 `--watchdog`（它只允许一个名为 `cmd_vel_watchdog` 的额外发布者）：

```bash
python3 /tmp/base_forward_probe.py --axis x --speed 0.05 --duration 3 \
  --check-silence-stop --silence-window 1.5 --confirm-wheel-stop --watchdog \
  --log-csv /tmp/silence_wd-1118.csv --evidence-out /tmp/silence_wd-1118.md
```

**期望：** `SILENCE_STOP_OBSERVED`，最后一条指令后约 0.4 s 起减速、约 1 s 内近零。若仍是 `NOT_OBSERVED`，先确认看门狗在运行、节点名是 `cmd_vel_watchdog`、`--timeout` 没被改大。

## 6. 边界：这些结论不能越界

- 本检查**不等于**拔线、计算板掉电或强杀进程的失联测试。
- `SILENCE_STOP_OBSERVED` 可能来自上位机驱动或串口读循环，**不能证明 MCU 有独立超时保护**；要证明它，需要固件源码、协议或示波器级证据。
- 1.5 s 是脚本观察上限，不是厂家指标，也不是比赛标准。
- 架空结论不外推到地面方向、里程计精度、导航或寻物闭环。

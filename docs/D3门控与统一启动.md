# D3：门控与统一启动

日期：2026-11-18。**x轴架空基本流程已验证：静态禁动、授权运动、断流停车、超时锁定、未授权请求零反馈、手动重授权恢复及再次停车。两次近零反馈约0.986s/1.033s，均有兜底前停转目视确认。其他故障仍待验证，不放行地面自动运动，MCU独立保护未解决。**

## 新链路

```text
控制脚本 → /cmd_vel请求 → cmd_vel_gate → /cmd_vel_safe输出 → 重映射后的wheeltec_robot → 串口 → MCU
```

[cmd_vel_gate.py](../tools/cmd_vel_gate.py)不订阅自身输出，零速不会刷新上游请求时间。默认DISARMED，每个20Hz停止态定时周期尝试补零；使用steady定时器和单调超时。深度1队列，不由定时器重复旧非零速度。

请求超时0.4s、odom接收过期0.35s、反馈时戳重复/倒退、帧不符、非法轴、非有限值、超速和ROS图冲突会阻止或锁定运动；恢复健康不自动解除锁定。手动arm要求新鲜静止反馈、预期图且当前没有请求发布者。测试限制为平面合速度≤0.05m/s、yaw≤0.15rad/s。

[guarded_base.launch.py](../tools/guarded_base.launch.py)统一启动门控及安装版base_serial，在作用域内重映射驱动输入，不改厂商文件、不编译、不刷机、不自动授权。不启动雷达、SLAM、完整TF或旧看门狗。额外的red_vel、robot_recharge_flag、set_charge移至/d3_unused下，避免默认入口误接，但这不是访问控制。

旧cmd_vel_watchdog.py与历史证据保留。它同Topic订阅/补零，自身消息也刷新活动计时，纯逻辑测试不能证明真实ROS下持续20Hz补零。**新入口不与旧版并用，也不使用探针的--watchdog模式。**

## 第二步：架空静态启动，暂不授权

确认四轮离地、车体稳固、物理电机停止方式可用，旧驱动与旧看门狗已退出。第一处小车shell：

```bash
ros2 launch /tmp/guarded_base.launch.py
```

入口先运行门控的--check-imports，失败时不会启动本次底盘；它仅检查Python依赖，不创建ROS节点或发运动指令。检查成功后预期串口打开，门控DISARMED，轮子静止。第二处小车shell只检查：

```bash
ros2 node list
ros2 topic info /cmd_vel --verbose
ros2 topic info /cmd_vel_safe --verbose
timeout 8s ros2 topic echo /cmd_vel_gate/state --once
timeout 8s ros2 topic echo /odom --once
```

/cmd_vel订阅者应为cmd_vel_gate，wheeltec_robot不直接订阅它；/cmd_vel_safe只有门控发布，wheeltec_robot订阅；/odom单一来源，帧为odom_combined/base_footprint且新鲜。此入口不含完整导航TF，不能据此开始建图。

启动失败、图不符或意外转动时停止测试并保存输出，先确认物理停转，不反复启动重试。门控不能强制压制其他发布者的非零指令。

## 静态检查通过后才安排的架空复测

以下为复现执行卡，基本x轴流程已于11月18日执行（见末尾记录）；恢复测试时仍须重新检查条件。每次先停止上一次控制脚本、确认四轮停稳且请求端无发布者，再授权：

```bash
ros2 service call /cmd_vel_gate/arm std_srvs/srv/Trigger '{}'
```

只有success=true才继续。门控可保持等待新的控制源；请求流开始后再静默超过阈值则锁定。一次测试结束或故障后需重新授权，持续非零请求不能自行解锁。

```bash
python3 /tmp/base_forward_probe.py --axis x --speed 0.05 --duration 3 --check-silence-stop --silence-window 1.5 --confirm-wheel-stop --log-csv /tmp/d3-gate.csv --evidence-out /tmp/d3-gate.md
```

不加--watchdog。记录DISARMED/COMMAND_TIMEOUT、近零反馈时刻、四轮是否在探针零速兜底前实际停转；目视与反馈分开记录。另用唯一会话名避免覆盖证据。手动禁动可用：

```bash
ros2 service call /cmd_vel_gate/disarm std_srvs/srv/Trigger '{}'
```

它不是物理急停。后续还须架空验证重复授权、反馈异常、竞争来源和正常退出。旧controller_death_test.py是在2秒后停发、继续观察约5秒，历史结论按指令静默理解，不证明真正进程猝死。

## 保护边界

- 门控/驱动被强杀、串口失效、计算板掉电、MCU故障不由这套同主机软件独立兜底。门控退出时launch打印物理停止提示，不自动重启；应立即使用物理电机停止方式。**MCU独立超时仍是阻塞项。**
- 正常退出尝试1秒零速也不是保证，尤其驱动已经退出时。ROS图与新消息不证明实际电机、编码器或完整安全链健康。当前不安排拔线、掉电或强杀驱动试验。
- 尚未纳入雷达、相机、定位、TF、局部地图健康和制动距离，不是最终比赛安全系统。直接发布/cmd_vel_safe或/d3_unused仍可能绕过保护，不能运行此类发布器。
- 固定限速仅为这轮架空测试边界，不是制动能力实测值或比赛推荐值。

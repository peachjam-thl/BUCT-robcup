# 无线遥控与热点接入

日期：2026-11-23。记录本车无线控制的两种可行方案、实测结果，以及当天踩到的四个坑。**密码不入库**：AP 口令以车上 `/etc/hostapd.conf` 为准，热点口令由团队线下管理。

## 结论先看

| 方案 | 做法 | 电脑能上网 | 适用 |
| --- | --- | --- | --- |
| A：小车做 AP | 车上启 `hostapd` + `isc-dhcp-server`，电脑连小车热点 | ❌ 连上就没外网 | 现场没有路由器、也不需要 AI 在线时 |
| B：都连手机热点（推荐） | 手机开热点，小车和电脑都连它 | ✅ 走手机流量 | 需要一边扫图一边用云端工具 |

**核心原则：控制端与被控端必须在同一网段、能互相路由。** 小车在手机热点、电脑在校园网属于两个网络，默认不可达——手机热点是 NAT，没有公网入口。

## 方案 A：小车做 AP（镜像自带配置，可直接启用）

镜像里已有 `/etc/hostapd.conf`（`ssid=WHEELTEC_RDK_X5_humble_04`、`hw_mode=g`、`channel=6`、WPA2）与 `isc-dhcp-server`（`INTERFACESv4="wlan0"`），小车地址固定 `192.168.0.100`。

```bash
sudo bash tools/wifi_ap_up.sh      # 停客户端 supplicant → 交出 wlan0 → 起 hostapd → 起 DHCP
sudo bash tools/wifi_ap_down.sh    # 还原成 NetworkManager 客户端模式
```

电脑连上热点后：`ssh wheeltec@192.168.0.100`。

**实测代价**：电脑切到该热点后没有外网，云端模型随之断线。若还需要 AI 在线，用方案 B。

## 方案 B：都连手机热点（推荐）

车上执行：

```bash
sudo bash tools/wifi_join_hotspot.sh "热点名称"
```

脚本会退出 AP、清理地址、交回 NetworkManager、扫描并连接，Wi-Fi 密码由 `nmcli --ask` 交互输入。连上后打印 `IP4.ADDRESS`，例如 `172.20.10.2/28`。

电脑连同一个热点后：`ssh wheeltec@<上面打印的地址>`。

**注意**：手机热点用 DHCP，地址可能每次变化；需要固定时，把该连接的 IPv4 改成 manual（同网段空闲地址、网关与 DNS 指向热点网关）。

## 坑 1：`ROS_DOMAIN_ID=10`

`.bashrc:131` 有 `export ROS_DOMAIN_ID=10`。从 Windows 非交互 SSH 执行命令时不加载 `.bashrc`，默认 domain 0，`ros2 node list` / `ros2 topic list` 会一片空白，容易误判成"ROS 挂了"。

所有远程脚本都要先：

```bash
export ROS_DOMAIN_ID=10
source /opt/ros/humble/setup.bash
source ~/wheeltec_ros2/install/setup.bash
```

## 坑 2：重启后只起键盘不会动车

`wheeltec_keyboard` 只是发布 `/cmd_vel`；底盘、雷达、EKF、SLAM 需要分别启动。判据：

```bash
ros2 topic info /cmd_vel     # 必须有 wheeltec_robot 作为订阅者
ros2 topic hz /odom          # 应为约 20 Hz
```

本次排障时 `/cmd_vel` 是「1 个发布者、0 个订阅者」——键盘在发，没人收。

## 坑 3：键盘进程变孤儿

SSH 会话断开后，`ros2 run wheeltec_robot_keyboard` 进程可能继续存活并在后台持续发零速，此时重新开键盘、按键都没反应。

处理：先 `pkill -f wheeltec_keyboard`，确认 `/cmd_vel` 发布者为 0，再在新终端重开。

## 坑 4：时间跳变打断 SLAM

本车 RTC 每次断电回 `2000-01-01`，当前 `NTP service: n/a`。连上外网后系统时间可能被某机制一次性校正，slam 会因变换缓存早于消息时间而丢帧：

```text
Message Filter dropping message: frame 'laser' ...
reason 'the timestamp on the message is earlier than all the data in the transform cache'
```

表现是"车在动、地图不涨"。处理：**先对时，再建图**；一旦中途发生跳变，重启 slam_toolbox 并重新开始。

```bash
date                                   # 建图前确认
pkill -INT -f 'slam_toolbox|async_slam'; sleep 3
ros2 launch slam_toolbox online_async_launch.py use_sim_time:=false slam_params_file:=<params.yaml>
```

## 验收判据

- `ping <小车IP>` 通；
- `ssh wheeltec@<小车IP>` 能登录；
- `ros2 topic hz /odom` 约 20 Hz；
- `map_status.py` 显示 `tf map->odom_combined / odom_combined->base_footprint / base_footprint->laser` 三项都 ok；
- 键盘遥控时 `known` 栅格数随移动增长（`minimum_travel_distance=0.5 m`，走半米才新增节点，别用几厘米判断）。

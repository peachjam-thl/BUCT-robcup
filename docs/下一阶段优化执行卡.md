## 三项关键判据

### 时间：检查本轮数据一致性

- 11月18/21日已有日期回2000年的记录；11月23日联网后又出现2000年跳到当日并导致SLAM丢帧，重新启动SLAM后完成采集。时间保持与实际对时机制未验收；历史ntp曾同步，不能仅凭NTP service:n/a认定当前没有任何对时进程。
- 建图前核对实机节点use_sim_time=false，雷达/里程计/TF采用一致时基，消息新鲜且扫描时间对应的TF可查询。若跨设备生成时间戳，还需核对设备间偏差；采集期间有明显时钟跳变则暂停并复查。
- System clock synchronized的yes/no只作同步状态证据，不单独判定可以建图。yes不证明传感器和TF已配套；no也不直接证明单机ROS不可用。ROS时间与单调时间不同，不能假定ROS时间总是单调递增。
- 若确需手动对时，先停止相关ROS采集/建图节点，在采集前处理并记录；手动改日期不证明NTP同步或RTC保持已经修复。不在建图期间调整时钟，也不据此追加时间服务替换、系统升级或重启。

### 停车：操作措施与独立保护分开验收

- 已有证据是无保护的ROS指令断流窗口内，5秒仍有非零速度反馈；早期窗口的全程物理目视记录未补齐。它说明当时控制链未实现预期断流停车，不能单凭该实验断言MCU完全没有超时机制。
- D3基本架空流程已有证据，但门控异常退出、主机故障、串口断连及MCU独立超时等未整体验收；不能把“存在持续运动风险”写成“主机故障必定失控”，也不能按门控正常运行的结果推定故障时会停。
- 11月23日已有厂商直接控制链下的现场导航功能记录，不能继承D3的门控验收；物理停止可达或有人值守也不代替独立停车证据。后续先核对实际速度来源和停止方式，按触发条件、预期时序、反馈与轮子状态分别验收；未完成的保护不因导航成功补勾，也不作为无人值守/整场放行依据。

### TF：检查每个子帧，不误判话题发布者数量

- laser是扫描帧，laser_link是URDF模型帧，二者是不同子帧。沿用原文件；不因laser_link的yaw=pi给laser追加旋转。
- 检查同一个子帧是否存在冲突父帧或重复发布来源；不是要求整个/tf_static只有一个发布者。该静态入口由robot_state_publisher及两个静态节点分别发布不同边，多发布者本身正常。
- 两项tf2_echo能查到变换不等于已排除全部重复来源；还须结合实际TF关系、节点与启动配置核对。/joint_states是默认显示关节角，不证明编码器、轮速或里程计；相机TF正常不证明相机驱动正常。

## 下一次到车旁的第一项

先读最新README、[11月23日日志](../日志/2026-11-23.md)与[Nav2执行卡](Nav2单点导航验证.md)，确认本轮供电、地址及时间。连接已有小车shell后只读检查：

```bash
export ROS_DOMAIN_ID=10
source /opt/ros/humble/setup.bash
source ~/wheeltec_ros2/install/setup.bash
date -Iseconds
ros2 node list
ros2 topic info /cmd_vel --verbose
ros2 topic info /cmd_vel_safe --verbose
ros2 topic info /map --verbose
```

domain10是11月23日现场值；若现场栈已改变，以实际进程配置为准。/cmd_vel_safe不存在也只作为诊断信息，不自动补起D3。查清速度来源、键盘孤儿、定位节点是否重复以及SLAM/AMCL职责后，必要时恢复唯一一套已记录入口；按当前实物位置给初值并用[定位检查工具](../tools/localization_check.py)确认对齐，再安排有现场停止条件的取消/停稳试验。历史初值不能作为通用启动坐标。

本轮取消试验应至少记录：目标与测试条件、取消请求及Action最终状态、反馈速度归零、实际轮子停稳及其时序。未取得结果前保持“未验收”；故障退出等测试须先设计受控条件，不能用直接强杀底盘或拔线替代准备。

系统维护单独安排：RTC保持问题继续保留；建图前核对本轮时间戳与TF的一致性，采集中发生时钟跳变则暂停并复查。重启、软件包修改与实车功能测试分开进行，不在本执行卡中追加系统升级或时间服务替换。

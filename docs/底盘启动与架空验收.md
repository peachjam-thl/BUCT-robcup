## 架空运动测试

使用 [base_forward_probe.py](../tools/base_forward_probe.py)，每次前置 1 s 零速，结束尝试连续 2 s 零速。

| 命令参数 | 反馈和用户观察 | 结论 |
| --- | --- | --- |
| x=0.03 m/s，1 s | 多次全零，四轮没动 | 首次电机响应未通过 |
| x=0.05 m/s，1 s | 独立 echo 捕获 linear.x=0.05、其余为零；短暂转动，打印反馈仍零 | 有动作，反馈尚不足 |
| x=0.05 m/s，3 s | 初段零；vx≈0.025–0.065，vy≈−0.007–0.021，wz≈−0.072–0.090；最后全零 | 用户确认四轮均转动并停下 |
| y=0.05 m/s，3 s | vy≈0.034–0.061，伴有其他轴小幅反馈及瞬态 wz≈0.104；最后全零 | 用户确认四轮均响应并停止 |
| yaw=0.15 rad/s，3 s | 前约 2 s 零，后 wz=0.151、0.125、0.192、0.150；vx 最高约 0.015、vy 约 0.026；最后全零 | 对应角速度反馈已观察，实际四轮停转待单独确认 |

初段零反馈原因未定位，不据此认定低速死区或固定延迟。架空跨轴波动不代表地面漂移或里程计误差，不据此直接调比例。

## 复现

车体稳固、四轮离地，避免滚轮夹点，电机电源停止方式可触及。驱动终端保持运行；不要同时启动遥控、导航或第二个底盘驱动。

Windows PowerShell：

```powershell
scp "D:\Personal\Desktop\LETSROS\tools\base_forward_probe.py" wheeltec@192.168.128.10:/tmp/base_forward_probe.py
```

第二处小车 SSH shell，逐条运行，每次确认停转后继续：

```bash
python3 /tmp/base_forward_probe.py --axis x --speed 0.05 --duration 3
python3 /tmp/base_forward_probe.py --axis y --speed 0.05 --duration 3
python3 /tmp/base_forward_probe.py --axis yaw --speed 0.15 --duration 3
```

需要留证或做断流检查时，按 [执行卡](停转确认与指令断流执行卡.md) 加 `--confirm-wheel-stop`、`--check-silence-stop`、`--log-csv` 与 `--evidence-out`。

默认 x/0.03 m/s/1 s；x/y 上限 0.05 m/s、yaw 上限 0.15 rad/s、时长≤3 s。脚本等待新鲜里程计与订阅者，检测竞争发布者；在反馈过期、用户中断等退出路径尝试发零速。这些检查依赖 ROS 图和消息接收，不能代替物理停止及 MCU 保护。

## 停转与断流实测（2026-11-18）

架空、USB SSH、`/odom` 19.96 Hz、`/cmd_vel` 0 发布者 1 订阅者。命令与完整输出见 [执行卡](停转确认与指令断流执行卡.md) 与 [日志](../日志/2026-11-18.md)。

| 测试 | 参数 | 反馈 | 现场观察 |
| --- | --- | --- | --- |
| yaw 停转 #1 | yaw 0.15 rad/s，3 s | wz 峰值 0.239，结束归零 | 四轮转动，跑完静止、干脆停住 |
| yaw 停转 #2 | 同上 | wz 峰值 0.242，结束归零 | 同上 |
| 断流 1.5 s | x 0.05 m/s，3 s | `SILENCE_STOP_NOT_OBSERVED` | 未盯窗口，记 unobserved |
| 断流 3.0 s | 同上 | `SILENCE_STOP_NOT_OBSERVED` | 同上 |
| 断流 5.0 s | 同上，逐 0.25 s 记录 | `SILENCE_STOP_NOT_OBSERVED`；静默段 vx 稳定在 0.05 | 同上 |

**判读：** yaw 的架空停转可记为已确认；断流的结论不是「窗口太短」——5 s 内反馈始终是 0.05 m/s，说明上位机驱动没有指令超时归零，下位机也没有可观察的独立超时。

随后补了上位机看门狗（[指令看门狗](指令看门狗.md)）：静默 0.4 s 补零。同一断流检查加 `--watchdog` 后变为 `SILENCE_STOP_OBSERVED`（约 0.96 s）；模拟控制器发 2 s 后直接退出，看门狗 0.4 s 补零、车辆约 0.9 s 后近零。该保护只在主机侧，不能证明 MCU 有独立超时。

为解决「反馈归零不等于轮子停转」与「记录不足以复核」，工具补充了操作员确认与证据留存，参数见 [tools/base_forward_probe.py](../tools/base_forward_probe.py)：

- `--check-silence-stop` 由仅 x 轴扩展到 x / y / yaw；静默观察窗口用 `--silence-window` 设 0.5–5.0 s，默认 1.5 s。
- `--confirm-wheel-stop` 在零速兜底结束后询问「四轮是否完全静止」；静默检查同样在兜底**之后**询问「兜底零速之前是否已停转」，回答不会拖延停车。回答记入证据，`unobserved` 不算通过。
- `--log-csv` 每 0.25 s 记录一次指令与 `/odom` 反馈，`--evidence-out` 写出可直接粘贴的 Markdown 证据块。
- 新增参数只增加观察与证据，不改变限速（x/y ≤0.05 m/s、yaw ≤0.15 rad/s、时长 ≤3 s）与退出时的 2 s 零速兜底。

**执行条件**：四轮离地、能立即断电、操作员现场观察轮子；本次已满足并执行。换场地或换固件后复测仍需同样条件。

技术判据不变：正常命令阶段后暂停发布速度消息，自最后一条非零指令起进入静默观察；开始时须反馈新鲜且该轴反馈超过基线（x/y 0.02 m/s、yaw 0.06 rad/s），近零判据为 |vx|、|vy|≤0.01 m/s 且 |wz|≤0.04 rad/s，需持续接收至少 0.20 s。

- SILENCE_STOP_OBSERVED：满足近零反馈，仍须操作员确认四轮是否在零速兜底前停转；时间仅为接收时刻估计。
- SILENCE_STOP_NOT_OBSERVED：窗口内未见稳定近零，不排除更长固件超时，不能记为保护通过。
- SILENCE_CHECK_INVALID 或其他中断：条件不足或检查终止，不作停车结论。

默认 1.5 s（可设 0.5–5.0 s）是脚本观察限制，非厂家指标或比赛标准；加长窗口时轮子可能在指令静默后继续转更久。本测试不等于物理拔线、掉电或强杀进程；仍须架空且能立即切断电机电源。
